3.0 is a ground-up rewrite of HeimdallWhitelist 2.x, and 3.0.1 is its first stable release. There is no stable 3.0.0: the update checker in the release candidates reads `3.0.0-rc.25` as newer than `3.0.0`, so a server on an rc would never have been offered it. 3.0.1 sorts above every rc, and fixes that ordering for future releases.

One jar runs on every platform: Paper and Spigot 1.8.8+ (Java 8+), Folia and Canvas, Velocity 3.4.0+ (Java 17+), and BungeeCord or Waterfall.

### Upgrading from 2.x

Replace the 2.x jar with this one and remove the old jar (the names differ, so both would load). On first boot the plugin reads the 2.x config (`plugins/HeimdallWhitelist/config.yml` on Paper, `plugins/heimdall-whitelist/config.json` on Velocity), writes `bootstrap.yml` from its credentials, renames the original to `*.v2-backup`, and stages the rest for the dashboard. Finish with `/hd setup <code>` (`/hdp` on a proxy). BungeeCord had no 2.x build, so a BungeeCord proxy is always a fresh install.

### What's new in 3.0

**Setup and running**
- `/hd setup <code>` connects a server straight away, with no restart and no file to edit.
- Every feature is a module (`whitelist`, `rolesync`, `punishments`, `offenses`, `bridge`, `console`, `health`) switched on and off per server from the dashboard, live. `/hd enable|disable <module>` is a local override that works while the bot is unreachable.
- Each install works out its role (standalone, proxy gatekeeper, backend enforcer) from the platform and its proxy forwarding settings. Override with `role:` in `bootstrap.yml`.
- Hot-swappable core on Paper, Velocity and BungeeCord: `/hd update` installs a new release and swaps it in live when the shell contract allows, otherwise on the next restart.
- `/hd status` is one readable screen (bot, tunnel, modules, mirror, updates) with `status bot|modules|server|all` detail views.
- Server identity is bound to the install, so a copied server directory cannot impersonate the original (`/hd identity`, `identityCheck`).

**Whitelist and linking**
- Login gate with a local mirror of the whitelist, kept in sync when the bot says it changed, and a bounded wait so a slow bot never hangs a login. Respects another plugin's refusal.
- Linking and role sync work without the whitelist module (link-only networks).
- A pending link code is shown in game, as a dialog on new Paper.

**Role sync**
- Discord roles to LuckPerms groups, and in-game group changes reported back to the bot (reverse sync).
- Rank-to-role sync covers a rank held before the player linked, and removals that never reached Discord.

**Punishments**
- Native bans, temp bans, IP bans, mutes, warns, kicks and freezes, with history, an outage queue, hashed IPs, and muted-sign enforcement.
- Durations anywhere in the command, tab completion, `-s` silent (permission-gated), `-h` hidden, and composable branded screens.
- Punishments are announced once, by the outermost server.
- Muted players are blocked from blocked commands and their subcommands, see the full mute screen once and a one-line reminder after, and staff are alerted when a muted player tries to talk.
- Warns are shown to the player exactly once.
- `/hd case note` adds a note to a Heimdall case.
- LiteBans: an event hook that reports LiteBans punishments and lifts to Heimdall, lifts a Heimdall revoke in LiteBans too, and an import (`/hd import`) with a preview that survives a real database. Writes from the hook are durable across outages.
- Importers for AdvancedBan, BanManager and vanilla ban JSON.
- `HeimdallPunishments` API so other plugins can ask who is muted.

**Offences**
- `/offend` with escalation tiers, including offline name resolution.

**Chat bridge**
- Chat, joins, leaves and deaths to Discord and Discord messages back in game, shipped the moment they are said.
- Per-server `relayEvents` gate for joins, leaves and deaths.
- ChatControl channel awareness, and item images for ChatControl `[item]` shares.
- Vanished players' joins, leaves and deaths are never relayed (PremiumVanish, SuperVanish).

**Dashboard support**
- Live console streaming and remote commands, health (TPS, memory, players), MOTD and favicon, live player list, and remote update requests.

### Fixed since rc.25

- README rewritten for server operators.
- Update checker orders release candidates below their release, so `3.1.0` will be offered to a server on `3.1.0-rc.N`.
- `/iphistory` no longer fails when a player logs in while it runs.
- `heimdall.punishments.<verb>` alone allows the matching `/hd` punishment command; `heimdall.admin` is no longer needed.
- Freeze: `/hd freeze` and `/hd unfreeze` hold a player in place for checks, in LiteBans hook and replace mode, with the `heimdall.punishments.freeze` node; staff-only chat; proxy commands blocked; an optional ban for logging out while frozen. The dashboard Freeze option, the editable freeze message, the logout-ban toggle and `/mc-punish freeze` arrive with the next Heimdall release; until then the plugin uses the built-in message with the logout ban off.
- A backend behind a proxy that does not run Heimdall now runs standalone, so IP, country and subnet bans, punishment announcements and join role sync work there. The bot tells a backend when no Heimdall proxy is registered in its Discord server, and the plugin applies it from the next restart (`/hd status` says when one is due). If you add Heimdall to the proxy later, put it in the same network as its backends, run `/hd reload` on each backend, then restart it. Needs the matching Heimdall bot release; `role:` in `bootstrap.yml` still overrides.
